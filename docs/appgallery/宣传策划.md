# SiteCam 鸿蒙商店宣传策划

状态：已按用户要求生成三张宣传概念样图，待用户审阅，尚未上传商店素材。样图见 [宣传样图](宣传样图/生成说明.md)。

用户补充的重要卖点：鸿蒙多种屏幕形态适配。将普通直屏、阔直屏、折叠屏与平板适配独立成图，与“工程人自己做”“工程资料整理”并列为重点；不宣传所有机型均已完成验证。

## 核心定位

**工程人自己做的工程水印相机。**

从现场记录到资料交付，围绕真实工程工作来介绍功能。先讲遇到的麻烦，再展示怎么解决，让一线人员看懂怎么用，让项目经理看懂怎么管，让老板看懂资料怎么交代。用具体场景说服，不讲技术实现。

主标题候选：**工程人自己做，更懂现场怎么记。**

辅助句候选：**拍摄带水印，资料按工程整理，问题随照片跟进。**

行动句候选：**下一个工程，试着从第一张照片开始整理。**

这些是策划用的文案方向，不是已定稿的商店宣传语。

## 对谁说、解决什么

| 读者 | 现场常见麻烦 | 宣传重点 |
| --- | --- | --- |
| 施工、巡检人员 | 工程来回跑，照片容易混；拍完又要补地点、写说明 | 按工程拍摄、时间地点水印、现场标注 |
| 项目经理 | 翻相册找资料费事，问题拍了却不好跟进 | 工程分类、日期筛选、问题等级和处理状态 |
| 老板、负责人 | 汇总时资料零散，交接不清楚 | 工程资料集中整理、清单和报告、整包导出 |

## 图片内容安排

先按六张规划，正式数量和尺寸以商店上传页为准。每张只讲一个主要收益，放一个明确可见的功能证据。

| 顺序 | 文案方向 | 展示内容 |
| --- | --- | --- |
| 1 首图 | **工程人自己做的工程水印相机** | 干净的现场拍摄界面，突出品牌与真实工程用途 |
| 2 工程整理 | **工程再多，照片也要分得清** | 工程列表和切换；展示虚构工程、线路名称 |
| 3 拍摄记录 | **时间、地点、工程，拍下就记清** | 实际水印样式和字段；注明地点需授权且依设备定位情况 |
| 4 现场标注 | **问题在哪，直接标给人看** | 箭头、圈画、文字标注；保留原图与独立成品 |
| 5 问题跟进 | **从发现到处理，跟着照片看进度** | 待处理、处理中、已完成等实际状态；不暗示多人实时协作 |
| 6 资料交付 | **交资料，按工程整包带走** | 工程包导出、照片与清单；不暗示接入第三方验收系统 |

## 视觉方向

推荐“清楚的工程资料页”风格：浅灰或米白底、深灰标题，少量工程黄作强调；应用截图保留真实配色。字体端正、标题大、留白够，像整理得好的项目汇报材料，避免像促销传单。

以当前签名版真实截图为主，必要时配一小块克制的现场照片。照片用演示素材，不出现真实客户名称、人员、车牌、精确地址或涉密工地。所有示例工程标注为演示。

不使用悬浮手机群、发光电路、满屏渐变、夸张光效和堆满文字的功能墙。不用生成图片伪造应用界面；生成能力只辅助背景或装饰，真实截图和最终中文排版单独合成。

## 宣传边界

- “工程人自己做”采用用户明确提供的产品定位，不补编开发经历、团队规模、客户名单或使用人数。
- 突出解决实际麻烦，不承诺“零遗漏”“效率翻倍”“绝对真实”“防篡改”“验收必过”或不存在的认证。
- 不把水印表述为法律鉴定、时间认证或不可修改证据。
- 不写团队云同步、多人协作、自动派单、云端备份等当前没有的功能。
- 视频、具体机型兼容性等尚未完成实机验收的项目不作为首屏卖点。
- 商店宣传只讲功能、使用场景和必要条件，不讲开发语言、签名、渲染方式等实现细节。

## 制作顺序与确认点

1. 先由用户确认主线、标题和视觉方向。
2. 核对真实签名版页面，使用虚构工程准备功能截图。
3. 先制作一张首图和一张功能图，直接展示给用户确认文案、密度、色彩和真实感。
4. 根据反馈完成整套，每张生成后均提供可查看图片，再确定是否上传。

后续按用户反馈完善视觉与文案；宣传概念样图须经用户审阅后再决定正式素材，不直接上传。
