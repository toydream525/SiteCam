# Android 0.3.0 屏幕适配规则

沿用已确认的鸿蒙方案，Android 0.3.0（13）统一实现。系统栏、切口与安全区域扣除后的窗口宽度为 x、高度为 y；相差不超过一个物理像素视为方屏。

- y > x：底部快门；x >= y：右侧快门，垂直居中。
- 横屏保留右手握持空间：普通控制组距右侧保留 58–68dp 空间，快门不贴边。留手空间计入控制区宽度，不再通过负偏移挤压变焦和模式。
- 竖屏保留原有抬高快门和底部握持空间，变焦组上移不得越过取景边界。
- 普通直屏、普通折叠外屏、小折叠内屏沿用手机布局。
- 普通折叠内屏、阔折叠内外屏、阔直屏、平板共用大屏布局。操作组收拢至最多 320dp 高；相册宽度至少 600dp 时左列表、右原有详情，列表 280–420dp，详情至少 320dp。
- 小折叠外屏固定右侧快门，操作栏 56dp，按钮 44dp；高度不足 156dp 时只保留快门。复杂页面提示展开，背后的编辑页面保留。
- 半折横向折痕：取景在上，操作在下。纵向分隔折痕：取景和操作避开折痕；狭长窗口使用较大的连续面板。
- 折叠、旋转只改变界面排版；照片选择、原图/成品选择、缩放及编辑状态保持。拍摄方向仍由既有方向设置控制，不重绘历史媒体。

使用 Jetpack WindowManager 1.5.1 的 FoldingFeature 和最大窗口指标；机型识别与物理屏幕比例作为小外屏、阔屏的补充判断。普通手机旋转不会单凭应用窗口宽度变成阔直屏。厂商小外屏是否允许第三方应用运行、实际折痕和握持体验仍需对应硬件检查。

官方接口依据：[WindowManager](https://developer.android.com/jetpack/androidx/releases/window)、[折叠设备支持](https://developer.android.com/codelabs/android-window-manager-dual-screen-foldables)。
