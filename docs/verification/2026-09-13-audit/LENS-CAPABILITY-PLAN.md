# 鸿蒙与安卓广角、主摄、长焦识别方案

日期：2026-09-13。目标版本：v0.3.1。状态：方案，尚未实施。

## 验收目标

识别设备真正向应用开放的广角、主摄和长焦，并能在对应拍照／录像模式下调用；倍率标签与实际使用能力一致。具有长焦硬件但系统未向当前应用开放，与设备没有长焦，必须区别说明。

普通直屏手机的鸿蒙竖屏倍率排列对齐安卓版。平板、阔屏手机和折叠内屏竖屏保持现有间距与布局规则；镜头识别适用于上述所有设备，不通过改变宽屏布局来解决能力问题。

## 能力识别与选择

1. **先枚举应用可见设备。** 保存前后置、明确相机类型、逻辑／物理关系、有效焦距或视角信息、变焦范围，以及照片／视频输出能力。深度等非普通成像设备不能混入前后摄切换列表；默认、未知类型不能被强行判为主摄或长焦。
2. **分开判断四层事实。** 硬件存在、应用可访问、当前输出模式可绑定、正在使用，是四种不同结果。用户界面只展示可用操作，诊断中说明受限原因，不把系统限制表述为无长焦硬件。
3. **优先选择合适的公开逻辑相机。** 若某个可绑定逻辑组已经包含可用广角、主摄和长焦，优先让系统按支持的倍率管理成员；只有独立后摄确实公开且支持当前输出时才使用独立选择路径。切换失败恢复原可用会话，保持原倍率与选中状态，并提示失败。
4. **确认镜头角色。** 优先使用平台明确的类型与成员关系，再结合等效焦距／视角和有效帧元数据验证。不同传感器的实际毫米焦距不能直接用来比较广角与长焦。仅获得变焦上下限时，只能确认可用视角／倍率范围，不能据此承诺使用了某个物理镜头。
5. **分开显示倍率与会话倍率。** 若独立长焦本身的原生视角相当于主摄约 3.2×，它自己的 1× 不能直接显示成主摄 1×，也不能再次给该会话乘上 3.2 导致二次放大。统一主摄参考倍率与每个会话的映射，以设备真实数据为准。
6. **入口来自实际能力。** 保留真正的最低倍率，例如 0.54，避免先取整到不支持的 0.5 再被过滤。可用的原生长焦倍率应有合理入口；数码变焦可保留，但不标作独立长焦或光学切换。实际镜头可能随光线、对焦距离或模式变化，应以读回结果确认，不能永远绑定“3× 就是长焦”的标签。
7. **按模式更新。** 拍照、录像及输出配置改变后重新检查可用范围与绑定结果。某镜头只支持拍照时，录像不展示成同样可用。仅旋转 UI 不应改变镜头分类；相机设备发生变化时重新识别。

## 双端落点与兼容

| 平台 | 后续实现要求 |
|---|---|
| 鸿蒙 | 在 `CameraService` 中补齐公开设备类型、场景输出、变焦范围与模式状态，供界面生成入口。API 12 基线使用该系统已支持的字段与接口；新系统的逻辑成员和焦距信息只能在可用时读取 |
| 鸿蒙新接口 | 本机 SDK 的 `cameraType` 自 API 10 提供；`lensEquivalentFocalLength`、`isLogicalCamera`、`constituentCameraDevices` 与 `lensFocalLength` 标注 API 24；`getZoomPointInfos` 标注 API 26。后两组都需要版本与能力判断，不能为了新设备识别破坏 HarmonyOS 5 / API 12 运行 |
| 安卓 | 从应用可见的 Camera2／CameraX 信息识别后摄组和物理成员，补充 `CameraCapability`；当前仅按前后置选择的路径需支持选择实际可用的后摄组。保留既有切换失败恢复机制，较旧系统缺少物理镜头字段时保留未知结论 |
| 两端界面 | 当前选中倍率来自成功应用后的状态；会话变化后重新同步。普通用户界面不显示相机 ID、HAL 等实现细节，确实受限时给出简短说明 |

以上 API 版本取自本机[CameraKit SDK 声明](/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/ets/api/@ohos.multimedia.camera.d.ts:1050)，实施时还需在目标系统和会话实测。使用应用实际可用的公开能力完成识别与切换，系统访问受限时保留明确结论。

## 验收矩阵

| 场景 | 通过标准 |
|---|---|
| 广角 → 主摄 → 广角，重复切换 | 每次可取得有效取景与成片；请求倍率、活动镜头／焦距和显示状态能互相解释，无黑屏、失效选中或卡住 |
| 独立长焦手机 | 确认长焦实际公开且可绑定；在适合光照和距离的场景取得真实活动镜头／焦距证据。只出现 3×、5× 按钮不能通过 |
| 有长焦硬件但未公开 | 明确记录硬件存在和应用访问受限；保留可用主摄／广角及数码变焦，不宣称调用成功 |
| 无独立长焦设备 | 高倍率仍可使用时标为倍率能力；不虚构长焦镜头，不把合理的数码变焦判为硬件异常 |
| 0.54 等边界倍率 | 广角入口不被候选过滤；点选后使用真实有效值，显示与调用一致 |
| 拍照与录像 | 分别取得有效照片／视频；录像时不使用拍照专属能力，已有录像失败项 H1 单独解决，不用镜头枚举通过替代视频通过 |
| 低光或近距离回退 | 若系统改用主摄裁切，诊断能够识别实际回退，不维持虚假的“正在使用长焦”结论 |
| 普通手机与宽屏设备 | 普通直屏鸿蒙布局对齐安卓；平板、阔屏、折叠内屏保持现有竖屏间距，各自可用镜头入口完整 |
| 新旧系统与重新进入相机 | API 12 不访问新系统专有字段；后台返回、会话重建和失败恢复后倍率、能力与实际会话同步 |

最后验收必须包含应用实际可访问的长焦手机和实际成片。当前小米 14 公开能力受限的证据不能替代一次成功的独立长焦调用，也不能据此承诺通过普通应用即可解除系统限制。
