# 鸿蒙与安卓工程包切换方案

日期：2026-09-13。目标版本：v0.3.1。状态：方案完成，尚未实施。

## 目标与已确认问题

让用户能够从工程 A 快速切换到工程 B，并随时看清后续照片、视频属于哪个工程。两端采用相同的操作含义，适配各自的手机、平板和折叠布局。

用户已确认两端无法顺畅地自由切换已有工程包。本次代码核对发现：工程卡片主要用于查看资料，“设为拍摄工程”隐藏在“更多”中，选择后没有一致的返回相机流程；已锁定或归档的工程又被禁止设为当前拍摄工程。这些行为叠加，使“查看了一个工程”“选中了当前工程”“允许新增拍摄”难以区分。

本条覆盖工程切换及其与锁定的关系。尚未确认锁定字段保存失败、重启后丢失或锁定后仍能拍摄，不把这些情形列为已经复现的故障。方案保留“锁定拍摄”的原有用途：限制新增照片与录像，既有资料仍可查看、编辑和导出。

## 推荐操作

### 相机：两次点击切换

1. 相机顶部持续显示“当前工程包：工程 A”，工程名称本身是完整的点击区域。
2. 点击工程名称，打开“切换工程包”面板。列表显示工程名称、线路、当前标记和拍摄状态；点工程 B 即执行切换。
3. 保存选择成功后收起面板，回到相机，顶部名称和水印同时更新为 B，并短暂提示“已切换到工程 B”。后续新拍照片、视频归入 B，原有资料不移动。

普通切换不增加确认弹窗。当前工程仍可点击，直接关闭面板返回相机。切换失败时保留原来的工程与水印，提示原因，面板中允许重试。

快捷面板显示当前工程及最近使用的未归档工程，顺序在面板打开期间保持稳定；“全部工程包”进入完整管理页，“新建工程”创建成功后直接切换。当前工程即使已归档，也应显示其状态，不让当前项消失。

### 工程管理：明确区分切换与查看

每张工程卡片显示名称、线路、照片／视频数量，以及可同时出现的“当前”“已锁定拍摄”“已归档”标记。

- 主操作：“切换到此工程”；当前项显示“返回当前工程”。操作成功后回到相机。
- 并列操作：“查看资料”；只浏览该工程，当前拍摄工程不变。
- 保留可见的“编辑”“导出”，并直接显示“锁定拍摄／解锁拍摄”；归档工程显示“恢复工程”。

卡片文字和空白区域不再承担另一种隐含的切换含义。批量模式继续使用明确勾选，切换工程操作在批量模式退出后使用。搜索、分类、排序和归档筛选沿用现有管理能力，不借此次改造重做资料管理。

### 锁定：可切换，拍摄受限

| 工程状态 | 能否设为当前工程 | 相机反馈与后续操作 | 既有资料 |
|---|---|---|---|
| 正常 | 可以 | 显示“可拍摄”，后续照片和录像归入该工程 | 按现有规则查看、编辑和导出 |
| 已锁定拍摄 | 可以，保持锁定 | 显示“已锁定拍摄”，快门和录像入口停用，提供“解锁拍摄”；顶部仍可切换其他工程 | 保持可用 |
| 已归档 | 可以，保持归档 | 显示“已归档”，禁止新增拍摄，提供“恢复工程” | 保持可用 |
| 同时已归档、已锁定 | 可以，两个状态分别显示 | 先恢复工程；恢复后仍锁定，需显式解锁才能拍摄 | 保持可用 |

锁定当前工程不会替用户换到其他工程。切换到已锁定工程不会自动解锁。恢复归档不会自动取消锁定。

锁定和解锁使用明确动词，成功后更新状态并提供一次“撤销”；不另加普通确认弹窗。撤销同样检查工程是否正在拍摄或保存，不能越过操作限制。旧资料的删除、移动等行为沿用既有规则，不把本次“锁定拍摄”扩大为资料只读功能。

## 拍摄归属与异常行为

当前工程、正在查看的工程、批量勾选工程分别保存，查看资料和批量操作不应改变当前工程。工程是否锁定、是否归档分别维护，不能用其中一个字段代替当前工程选择。

| 场景 | 方案要求 |
|---|---|
| 快速连续选择 B、C | 同时只提交一个切换请求；完成前显示“切换中”，不让较早请求覆盖较晚状态 |
| 正在拍照、录像或保存 | 当前工程选择暂不可用，显示“正在拍摄／保存到工程 A”；完成后用户可立即切换，不暗中排队自动切换 |
| 保存期间锁定该工程 | 拒绝这次状态变更并说明原因；其他空闲工程不受影响 |
| 已按下快门后切换工程 | 该次拍摄的工程 ID、水印信息与归属已冻结；后续切换不得改变这次记录 |
| 目标工程已被删除 | 切换失败，刷新列表，保留仍存在的当前工程 |
| 当前工程已删除或未选择 | 明确显示“请选择工程包”，提供选择和新建入口；不显示虚假的默认工程，也不自动选中另一个工程 |
| 锁定／解锁保存失败 | 保持原状态并提示失败，不先显示成功；重试读取最新记录 |
| 重新打开应用 | 恢复已成功保存的当前工程与独立的锁定、归档状态 |

更新选择时读取目标工程的最新状态；更新锁定时只修改锁定字段。两端都以持久化成功作为成功反馈依据。拍摄开始还须再次检查工程是否存在及能否拍摄，不能只依赖按钮是否亮起。

## 尺寸与可达性

手机竖屏使用底部选择面板；横屏、平板和宽窗口优先使用工程名称附近的选择面板，全部工程仍可进入管理页。横屏必须能看到当前工程名，不只显示文件夹图标。

大字号和长工程名允许换行，线路作为次要信息；状态不能只靠颜色表达。切换、解锁和返回入口均有清楚文字及足够点击区域。切换面板列表可滚动，当前工程与退出入口容易找到；不挤占快门操作空间，竖屏保留底部握持余量，横屏保留右侧握持余量。小折叠外屏单独使用简化布局，仍保留当前工程与一键打开选择面板的入口。

## 实施与验收

实施顺序：先统一工程选择／拍摄许可规则及成功失败反馈，再接入相机快捷面板和工程卡片操作，最后完成多尺寸布局与真机验收。鸿蒙先验收，再按相同场景验证安卓；目标版本统一纳入 v0.3.1。

| 验收场景 | 两端应达到的结果 |
|---|---|
| 普通 A → B → A，各拍一张 | 每次两次点击完成切换；顶部、水印、成片归属始终一致；原有资料不移动 |
| 查看 B 资料后返回 A 相机 | 当前工程保持 A，未发生隐式切换 |
| 锁定当前 A，再切换 B | A 保持锁定，B 可正常拍摄；重开应用状态保持 |
| 选择已锁定 C | C 成为当前工程但不能拍摄，明确显示解锁入口；解锁成功后才允许拍摄 |
| 锁定／解锁／撤销及失败重试 | 只改变目标工程的拍摄许可；状态、提示和持久化结果一致 |
| 同时归档和锁定 C，恢复归档 | 恢复后 C 仍锁定，不自动开启拍摄 |
| 拍照保存／录像中尝试切换或锁定 | 原拍摄归属稳定，受限操作有原因提示，无串工程或半切换状态 |
| 无工程、当前工程被删除、目标工程失效 | 可选择或新建，有明确空状态与错误反馈，不伪装为默认工程 |
| 新建、编辑、导出与批量选择 | 保留原有功能；查看、编辑、导出、批量勾选不会偷偷切换当前工程 |
| 普通手机、平板、横屏、大字号、折叠内外屏 | 工程名和切换入口可见，按钮不重叠，快门握持空间保留 |

浏览器中的交互示意使用虚构工程与临时状态，不访问手机或真实工程。本轮已检查快捷面板切换、卡片切换后返回相机、查看其他工程后当前工程保持不变、锁定工程禁止拍摄及显式解锁后可拍摄；模拟保存期间切换入口停用。320 px 和 736 px 预览下未发现横向溢出，检查时没有脚本错误。示意通过不能代替后续持久化、真实拍摄及跨设备验收。
