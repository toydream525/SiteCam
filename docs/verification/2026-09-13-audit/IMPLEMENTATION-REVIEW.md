## 原生视频时间戳审核依据

[OpenHarmony NativeWindow 实现](https://raw.githubusercontent.com/openharmony/graphic_graphic_surface/master/surface/src/native_window.cpp)在请求缓冲区时将窗口时间戳复制到缓冲区，提交时使用缓冲区中的值。替换 EGL 扩展时必须核对请求和赋值的先后，不能只在原提交调用处替换接口就认定正确。源码阅读仍不能代替实际输出帧时间和成品校验。

主路随后独立核对 `graphic_graphic_2d/frameworks/opengl_wrapper/src/EGL/egl_wrapper_display.cpp` 的 PresentationTimeANDROID 实现，确认其直接传递 SET_UI_TIMESTAMP。另发现单位证据存在版本边界：当前 SDK 关于纳秒的说明属于 API 20 起的 PTS-based rate-control 配置；OpenHarmony-5.0-Release 的视频编码示例使用微秒，hencoder.cpp 从 Surface 取得 entry.pts 后直接写入 AVBuffer，并与 repeatUs_ 相加。已要求实现路由记录差异，不能据新 SDK 说明认定 API 12 至当前厂商系统统一使用纳秒。输出时间轴和设备版本兼容性仍待验证。
