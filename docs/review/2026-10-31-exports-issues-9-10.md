# 工程导出、压缩包管理与 Issue #9 / #10 实施记录

日期：2026-10-31。分支：`codex/export-archive-management`。基线：`0fc34d1`（v0.4.3）。

## 完成的功能

- 安卓和鸿蒙单工程 ZIP 使用 `工程名_yyyy-MM-dd.zip`，日期为导出当天的本地日期；多工程导出保留各端原有命名。
- 同名文件保留旧包并增加序号。安卓导出结果读取保存位置实际使用的名称。
- 设置和导出面板增加“导出压缩包”管理，提供名称、日期、大小、刷新、多选、全选和确认删除。
- 管理包含应用导出位置已有 ZIP，可通过“添加旧包”选择历史目录；鸿蒙不支持选择目录的设备改用系统选择器添加旧 ZIP。
- 删除范围仅限所列 ZIP 文件，保留工程、照片、视频和目录；失败项单独提示。
- 工程分类旁显示已有创建日期，保留工程排序和直接可见的编辑、导出操作。
- 工程水印和文字标注分别支持导入 TTF / OTF 字体、选择字色和白板框；字体副本保存在应用内。
- 新增字段进入模板、拍摄快照和可编辑文字记录；旧记录缺少字段时保持原有默认样式。工程水印的照片及视频绘制共用字体与颜色配置。
- 新界面依据图 43、44 实现，并同步设计清单与契约。

## 审查发现及修复

| 触发条件 | 问题与影响 | 修复及证据 |
| --- | --- | --- |
| 安卓切换闪光模式后立即拍照 | 硬件更新等待设置写盘，界面已关闭而拍摄端仍可能沿用自动闪光 | 立即应用硬件状态，再保存设置；回归测试阻塞设置任务并确认相机状态已变化。 |
| 安卓关闭闪光时应用抓拍参数，或旧请求异步失败 | 关闭状态未进入 Camera2 参数；旧失败回调还可能清除较新请求的参数 | OFF 显式请求普通自动曝光及关闭闪光，失败回退保留 OFF，使用请求代次忽略过时失败。 |
| 鸿蒙重新创建拍摄会话且目标模式为关闭 | 原恢复逻辑跳过 OFF，仅更新本地状态，未明确下发关闭请求 | 有闪光能力时同时恢复 OFF；尚未进行反馈机型的实际暗处拍摄验收。 |
| 安卓已创建下载记录，打开输出流抛出异常 | 遗留未发布的下载记录 | 输出流创建失败时删除记录；测试通过注入写入失败确认无残留。 |
| 安卓 ZIP 写入期间取消 | 没有主动检查取消状态，可能继续完成发布 | 写入及发布前检查取消，失败清理未完成 ZIP；测试确认无 ZIP 残留且工程保留。 |
| 同一天重复导出同一工程 | 固定名称存在冲突，成功提示也可能与实际文件名不同 | 安卓查询实际名称、旧系统使用文件创建保留名称；鸿蒙选择空闲序号后保存。安卓回归确认旧文件内容保留。 |
| 导入字体改变文字宽高 | 固定估计边界与绘制字形不同，影响文字选中、拖动和白板框 | 新字体按实际字体测量，绘制和编辑边界共用对应字体；保留既有坐标转换与编辑记录。 |
| 鸿蒙查看关于页面 | 版本号固定为 0.4.2 | 改为读取安装包版本。 |
