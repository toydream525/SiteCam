# 0.3.0 屏幕适配共同基线

本规则由本轮用户确认，鸿蒙先实现，随后 Android 折叠屏适配沿用。Android 后续目标版本同为 0.3.0，本轮不修改 Android 界面或构建版本。

## 经验与规则

设备类型决定是否使用大屏分栏、是否简化外屏；快门位置由当前可用窗口宽高决定。不能用阔折叠代替小折叠验收，也不能用构建或几何测试代替真实画面。

x 是扣除系统栏、切口等安全区域后的宽度，y 是对应高度。y>x 时快门底部居中，x>=y 时右侧居中；相差不超过一个物理像素视为方屏。小折叠外屏固定右侧居中。屏幕方向和照片旋转分别处理。

| 设备/屏幕 | 方案 |
| --- | --- |
| 普通直屏、普通折叠外屏、小折叠内屏 | 原手机布局，快门遵循宽高规则 |
| 普通折叠内屏、阔折叠内外屏、阔直屏、平板 | 共用大屏响应式布局 |
| 小折叠外屏 | 简化取景和右侧拍摄；空间足够时增加最近照片、镜头切换 |

大屏相册在可用宽度达到 600vp 时左右分栏，左栏宽 280–420vp，右栏至少 320vp；空间不足时收起分栏。照片预览继续复用原详情，不重新渲染历史媒体。列表筛选不会自动替换右侧照片。

横向拍摄保留 Android 的左工具栏、中间取景、右操作区。大屏将相册/快门/镜头切换集中到最多 320vp 高的操作组。半折悬停先避开折痕，取景和控制区不跨越折痕；快门仍按宽高规则选择底部或右侧。

小外屏右栏宽 56vp，快门点击区域 44vp；可用高度不足 156vp 时只保留快门，足够时相册和镜头切换在快门上下方。复杂页面在外屏显示展开提示，保留内屏组件和编辑状态。

## 实现边界

- `CameraLayout` 统一计算取景、工具栏和操作区，密度用于一个物理像素的方屏容差。
- `DeviceLayoutProfile` 统一分配手机/大屏/小外屏方案。系统折叠状态涵盖双轴三折；机型信息识别 Pocket/nova Flip 与 Pura X 系列，并结合物理屏幕比例作保守后备判断。普通手机旋转不因窗口变宽而变成阔直屏。
- 旋转、折叠与展开保留当前资料、原图/成品选择、缩放、编辑草稿及拍摄设置；相机需要重新打开时保留镜头并按能力限制恢复变焦和闪光，常亮补光不自动重开。
- 旧媒体快照、模板和独立系统相册副本规则保持兼容，不迁移或重新绘制旧媒体。

## 验证要求

分别记录：纯规则/几何测试、模拟器真实页面、模拟尺寸控件测试、真机结果。小折叠小外屏与真实折痕行为在没有对应设备时只能记为待验证。阔折叠、普通手机或 Pocket 2 单屏规格模拟器都不能冒充小折叠外屏。

官方模拟器能力与屏幕配置参考：[命令行说明](https://developer.huawei.com/consumer/cn/doc/doccenter-deveco-studio/ide-emulator-command-line)。
