# 鸿蒙 0.3.0 统一屏幕适配审核

日期：2026-09-12。版本 0.3.0（versionCode 13），包名 com.sitecam.app。范围为本地开发、审核与签名前检查准备；Android 仍为 0.2.10，后续按同一方案升至 0.3.0。本轮没有 GitHub、官网或应用市场发布。

## 已修复

- 用可用宽高和实际屏幕密度统一快门位置：竖屏底部；横屏、方屏右侧；一个物理像素以内视为方屏。小折叠外屏固定右侧，不再使用底部横排。
- 普通手机/普通折叠外屏/小折叠内屏保持手机方案；普通折叠内屏、阔折叠内外屏、阔直屏、平板统一大屏方案。修正三折完全展开状态遗漏。
- 大屏相册 >=600vp 分栏，右侧沿用原详情组件；筛选不替换当前照片，点击同一照片不重建预览，切换照片才重置缩放。当前预览有选中标识，删除后清除失效预览。
- 左右分栏分享入口使用独立锚点，避免弹窗定位冲突。小外屏复杂页面使用提示覆盖，保留背后的内屏组件与编辑状态。
- 横向大屏收拢相册/快门/镜头切换操作组；横屏水印编辑面板不再挤进右侧小区域。
- 相机重新打开时复用镜头选择，变焦按当前能力范围恢复，恢复普通闪光模式，常亮补光不自动开启。
- 应用元数据、设置版本、诊断信息和离线说明统一 0.3.0。保留上一轮水印标签、顺序、恢复默认、旧快照及相册副本修复。

完整规则和后续 Android 基线见 [SCREEN-ADAPTATION.md](../SCREEN-ADAPTATION.md)。

## 验证证据

- Debug、Release 均构建成功，未配置签名。核心运行报告为 [api26-results.json](api26-results.json)，44 项中 43 项通过；唯一失败为缺少 H.264 编解码器。
- 设备方案检查覆盖普通手机、普通折叠内外屏、阔折叠内外屏、阔直屏、平板、小折叠内外屏与三折状态。几何检查覆盖竖、横、方形、不同密度的一像素边界和悬停折痕。
- 小外屏采用实际生产控件在测试模块中渲染五组模拟尺寸：96×96、120×180、180×120、327×327、320×240vp。逐一检查右栏、快门垂直居中、次要按钮边界并实际点击快门回调。见 [ui-cover-0.3.0.json](ui-cover-0.3.0.json)。这是模拟尺寸控件验证，不是小折叠真实外屏验证。
- 1080×1080px 专用方屏模拟器运行 Release，实际快门区域位于右侧，中心 y=540.5px；右操作区为 x=840–1080px。实际拍摄后相册出现资料，左右列表/详情同时显示；截图已查看，未发现按钮重叠或照片被列表遮挡。相片只保存在本地临时目录，不纳入仓库。
- 0.3.0 Release 在 SiteCamWideQA 三折模拟器复测两折展开、三折展开、折回单屏、再次两折展开：分栏按空间切换，当前照片和原图/成品选择保留，筛选不替换预览。左右横屏和快速水印编辑面板复测通过；最终屏幕截图已查看，快门在右侧垂直居中，变焦/模式/快门区域未重叠，长地址完整换行。见 [折叠页面记录](ui-fold-0.3.0.txt)。较早 0.2.10 的其他设备结果继续作为历史证据，不冒充所有 0.3.0 设备复测。

## 仍有问题及待验证

- 模拟器缺少 H.264，视频画面、音轨和硬件失败恢复仍未通过验收，不能记作成功。
- 没有真实小折叠外屏、真实折痕/悬停、阔直屏、阔折叠、平板握持证据；系统是否允许应用在小外屏运行也须在对应机型确认。Pocket 2 单屏规格模拟器和阔折叠均不能替代这项检查。
- HarmonyOS 5/API 12 配置继续保留，新三折状态通过已有接口返回值识别，未将新 API 强行用于旧系统；最低版本实机仍待测。
- 本机 DevEco 26.0.0.821、SDK 26.0.0.105 Release、Hvigor 6.26.4、OHPM 26.0.0.630 延用此前已核对的稳定工具链。没有开发者签名或真机连接，签名安装及覆盖升级尚未验证。
