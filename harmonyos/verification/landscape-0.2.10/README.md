# 横屏布局按 Android 对齐（2026-09-12）

> 历史批次记录；最新统一规则及交付版本为 0.3.0，见 harmonyos/SCREEN-ADAPTATION.md 与 verification/REVIEW-0.3.0.md。
本记录修正上一轮只验证交互和状态保留、没有核对 Android 横屏结构的不足。保持 0.2.10（12），未发布。

## 对照基准

Android CameraScreen.kt、CameraTopBar.kt、CameraBottomBar.kt：横屏由可用窗口 width > height 判定，左侧 102dp 工具栏，中间取景，右侧至少 160dp 拍摄区。工具纵向排列；右侧变焦和模式也是纵向，缩略图、快门、镜头切换在同一纵列。QuickWatermarkEditSheet 使用宽弹层。

## 修改

- CameraLayout 取消 >=840vp 或近方形大窗口即视为横屏的判断。横屏工具栏宽 102vp，占满可用高度；取景与右侧控制区连续排布，不再保留顶部 56vp 工具条。
- 右侧使用变焦列、模式列、快门列；快门列上方为相册、下方为镜头切换。短窗口使用紧凑按钮，正常横屏无需滚动寻找快门。
- 横屏快速修改面板居中展开，最大宽 640vp，不再挤进最小 160vp 拍摄区；内容可滚动，完成按钮保留。
- 拍摄页隐藏系统栏，离开拍摄页恢复；左右方向使用同一布局结构，不以相机传感器方向代替窗口判断。
- 保留既有竖屏、悬停避让与非拍摄页的大屏双栏设计。本轮对齐的是横屏拍摄与快速修改；不将此前非拍摄页状态测试称为 Android 视觉一致性验收。

## 检查

- 新增“横屏与Android三区规划一致”测试：手机、折叠、大屏、近方形、竖向大窗口共八种尺寸，检查判定、左栏 102vp、右栏 >=160vp、取景比例及区域相邻。
- 核心运行 41 项中 40 项通过，唯一环境阻塞仍为 H.264 视频编解码器。几何测试不能替代截图，UI 另以实际布局树核对左右工具区与按钮边界。
- 构建和运行日志保留 /tmp/sitecam-landscape-build.log、/tmp/sitecam-landscape-release.log、/tmp/sitecam-landscape-tests.log。

## 折叠相册与大屏拍摄补充

- 相册仅在折叠内屏展开且可用宽度 >=600vp 时启用应用内平行视界：左侧列表宽 280–420vp，右侧至少 320vp，覆盖原先未达到 840vp 的展开屏。普通直屏手机、折叠外屏和窄窗口仍使用单页导航；平板保留 >=840vp 分栏门槛。
- 右侧复用原照片/视频详情，保持原图/编辑成品切换、缩放、编辑、分享和系统相册副本入口。切换筛选及折叠旋转不主动更换选中资料；再次点击同一照片不重建预览，切换照片才重置缩放。
- 左侧高亮当前预览照片。删除当前资料时清空预览，避免再次显示已删除的文件；左右分享按钮使用不同锚点，避免分栏时弹窗定位冲突。
- 大屏横向拍摄延续左工具栏、中间取景、右拍摄区；仅折叠内屏的右侧相册/快门/镜头切换集中在最多 320vp 高的操作组内，快门保持居中。近方形及竖向展开屏仍按原生竖向拍摄结构，半折叠继续避让折痕。
- 这是应用内响应式分栏，不依赖系统强制拉伸或用户开启系统兼容模式。人体工学的握持舒适度仍需折叠真机验证。
